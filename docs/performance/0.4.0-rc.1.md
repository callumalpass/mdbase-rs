# Performance Qualification: 0.4.0-rc.1

Date: 2026-07-26

Workload: `benchmarks/release-v1.json`

Command: `./scripts/benchmark-release.sh`

This is the first enforceable release baseline for the typed-core
architecture. It is a regression budget, not a claim that every deployment
will reproduce these absolute timings.

## Method

The synthetic fixture contains 5,000 task records, 80 projects, and 100 files
with rename references. The seed and iteration counts are fixed by
`scripts/benchmark-release.sh`. The profiler runs an optimized build and writes
the complete JSON report to `target/benchmarks/release.json`.

The command exits nonzero when:

- the threshold schema or fixture size does not match;
- a required operation was not executed;
- a threshold is invalid;
- an observed p95 exceeds its versioned budget.

The report is written before threshold evaluation so a failure remains
diagnosable.

negative run with a mismatched 10-record fixture wrote its report and exited
with status 1.

## Interpreting the result

This release removes repeated expression parsing by compiling type match,
computed-field, lifecycle, and formula plans at collection open. Healthy
queries use the derived SQLite cache, while cache corruption or contention
falls back to an authoritative, fallible disk snapshot and reports degraded
health. The editor two-pass workload confirms snapshot reuse.

Runtime SQLite latency is protected separately: all blocking database work is
serialized on a bounded dedicated thread. The shared runtime tests exercise
memory, SQLite, and live PostgreSQL behavior; the benchmark above measures the
filesystem runtime/watch path.

Budgets intentionally leave headroom for CI and storage variance. Tighten them
only after comparable runs on multiple supported environments. Do not raise a
budget without attaching the before/after JSON reports and explaining the
tradeoff.
